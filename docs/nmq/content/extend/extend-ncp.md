# Extend NCP

NCP 的扩展点核心在“组件”而不是“零散工具函数”。任何新能力如果要长期接入平台，都应该优先封装为一个实现 `interfaces/ncp.Component` 的组件。

## 扩展模型

一个组件至少要回答四个问题：

1. 它的名字是什么。
2. 它会向其他组件暴露哪些接口标识。
3. 它在 `Init` 阶段需要什么依赖。
4. 它在 `Start` 阶段启动哪些服务或后台任务。

## 当前组件注入方式

`cmd/ncp/ncp.go` 通过 `RegisterComponents(...)` 完成注册：

- `dpproxy`
- `network`
- `dpcore`
- `webui`

这意味着新增组件时，除了实现本身，还需要把它加入统一注册流程。

## 推荐做法

- 复用 `ncp.NewComponentBase(ctx)` 获取日志、上下文和组件管理器。
- 用常量定义接口能力名，保持跨组件引用稳定。
- 把共享能力挂到 `GetInterface(uuid string) any`，不要让组件直接相互耦合具体实现。
- 把命令行入口、HTTP 监听或后台任务放在 `Start()` 阶段，而不是构造函数阶段。

## 常见可扩展点

- 新的观测能力，比如额外指标、告警适配器。
- 新的部署目标，比如不同集群类型或不同包格式。
- 新的管理端接口，比如数据库只读查询、审计流水、灰度策略。
- 新的 WebUI 面板或 API 提供器。
